## Safety limits and timeout observation

The local controller uses finite original P1 commands, verifies party identities, HP, EXP, location, restoration and original Journal/fresh Continue. Its logs record early stops rather than inferring wins. An independent review found residual uncertainty: some battle dialogue phases are shared, so phase and text checks do not prove recognition of every possible original choice. This is not established as a safe unattended long-run training driver. When uncertain, stop and inspect the actual screen.

A separate disposable diagnostic process was started from the unchanged 11-win Journal. One hundred original idle commands were queued; a timed signal terminated that exact isolated process while 99 commands were outstanding. The executed command count was 1 immediately after termination and still 1 two seconds later. The source Journal SHA-256 remained `094c1116dbf8e2fe52044c22f582521f4258d24e8522e4eb3ea05703bcc9178c`. Its [queued and executed commands](controller/) are included. This tests process termination with pending input under the observed Wine launch, not every possible process failure or launch configuration. If process selection or termination fails, manual process inspection is required. A timed-out Journal is valid only after a complete original save and independent byte-identical Continue.

The timeout helper and supervised pilot are research tooling with local absolute paths, not a supported game feature. Some of the included scripts were tightened after earlier logged trials. The logs therefore document the specific executions, rather than proving all older executions used the final guards.
